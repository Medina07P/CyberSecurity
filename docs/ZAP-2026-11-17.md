# OWASP ZAP como escáner (03_Scanners)

`03` tiene un tercer analizador web automatizado, junto a Nikto y Nuclei:
OWASP ZAP, en la opción **3 → 3** del menú de escáneres (Analizar una URL).

## Qué hace, y qué no

Solo **spider + pasivo**: rastrea la URL igual que un navegador seguiría
enlaces, y deja que el analizador pasivo de ZAP revise lo que el rastreo ya
vio pasar. **Nunca** Active Scan (inyección de payloads) ni AJAX Spider
(necesita navegador). Mismo nivel de intrusión que Nikto/Nuclei: tráfico
activo de verdad, pero sin explotar nada. Por eso no está en
`dangerous.txt`, igual que `nikto_scan.sh`/`nuclei_scan.sh` tampoco lo están.

## Cómo se instala

El binario `zaproxy` no viene instalado por defecto; la tecla `D` del
gestor (ver `docs/DEPENDENCIAS-2026-11-17.md`) lo lista y puede instalarlo
por `apt`. `python3-zapv2` (el cliente de la API) sí suele venir instalado
en Kali.

## Ciclo de vida del daemon — siempre propio de cada ejecución

Cada vez que se corre `zap_scan.sh`:

- Elige un **puerto libre** asignado por el kernel (nunca uno fijo — no
  choca con Burp en 8080 ni con otra instancia ZAP).
- Crea un **directorio de perfil temporal propio** (`-dir`); ZAP nunca
  escribe en el `$HOME` real.
- Al terminar (éxito, fallo o `Ctrl+C`), intenta apagar el daemon por su
  propia API (`core.shutdown()`) y, si no responde, por señal
  (`SIGTERM`/`SIGKILL`); borra el perfil temporal. Esto es **best-effort**:
  cubre salida normal e interrupción, no un `SIGKILL` del propio script ni
  una caída del proceso padre — mismo límite que otros módulos de este
  framework ya documentan en casos parecidos (p. ej. el coordinador de
  `08_Forensics`).

## Tope de tiempo

`ZAP_MAX_SEG` (variable de entorno, por defecto 300 segundos) acota spider
+ pasivo juntos. Si se agota, el rastreo se corta, el informe dice
explícitamente que es parcial, y el script sale con código 1 — nunca se
presenta un resultado parcial como si fuera completo.

## Encadenado en el flujo avanzado

Por decisión explícita del usuario, ZAP se ejecuta automáticamente —junto
a Nikto y Nuclei— sobre cada puerto web que `run_all_scanners.sh` descubre
(opción 5 "avanzado" del menú de `03`, y el `99` de flujo completo). Esto
añade minutos reales por URL (levantar el daemon + rastrear), no segundos
como Nikto/Nuclei: es un coste conocido y aceptado, no un descuido.

## Qué no se pudo probar en esta máquina

`zaproxy` no está instalado aquí, así que nada de esto se probó contra un
daemon ZAP real. Toda la suite (`tests/run_zap.sh`) corre contra
`tests/fixtures/zap_fake_api.py`, un servidor HTTP sintético que imita las
respuestas JSON de la API de ZAP — incluyendo una prueba de punta a punta
del wrapper completo (`zap_scan.sh`) con un `zaproxy` falso que de verdad
ata el puerto asignado y sirve esa API falsa, no solo un proceso vacío.
