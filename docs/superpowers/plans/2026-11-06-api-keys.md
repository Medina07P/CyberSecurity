# Claves de API en el gestor — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Que el gestor pida, guarde y proyecte las claves de API de las seis herramientas que las usan, y diga cuáles faltan sin imprimir ninguna.

**Architecture:** Un helper Python (`00_Config/scripts/api_keys.py`) con el registro YAML como fuente de verdad y un adaptador por herramienta que traduce y escribe en el sitio que la herramienta lee. El gestor gana una opción `K` que solo llama al helper. La suite nueva `tests/run_keys.sh` prueba registro, adaptadores, estados y seguridad con `HOME` y registro temporales.

**Tech Stack:** Python 3 + PyYAML (instalado), SQLite de la biblioteca estándar, Bash 5, las suites `tests/run_*.sh` existentes.

**Spec:** `docs/superpowers/specs/2026-11-06-api-keys-design.md`

## Global Constraints

- Todo el texto de cara al usuario en español, con el formato del repo (`✅`, `⚠️`, `❌`).
- Nada de `set -e` en bash; el helper Python devuelve códigos: `0` bien, `1` uso/valor inválido, `2` registro ilegible o no escribible, `3` alguna proyección falló (registro ya guardado).
- El registro y las proyecciones que creamos: `600`; los directorios nuevos: `700`.
- Nunca se imprime el valor de una clave: ni completo, ni recortado. Solo presencia y longitud.
- Escrituras atómicas (temporal en el mismo directorio + `os.replace`); un YAML ilegible **no** se sobrescribe.
- Sin `sudo`. Si algo exige root, se avisa y no se hace.
- Rutas resueltas desde la ubicación del fichero (`Path(__file__).resolve().parents[2]` para la raíz del framework), nunca desde `$PWD`.
- `.sh` y `.py` en LF. `bash -n` capturando stderr y `python -m py_compile` antes de dar nada por bueno.
- Los tests no tocan ficheros reales: `HOME` temporal, `KEYS_FILE` temporal, `KEYS_HARVESTER_DIRS` temporal.
- Nombres de campo del registro: los que documenta cada herramienta, en rutas con puntos (`theharvester.censys.secret`).

## Review Focus

- **Registro ilegible o corrupto**: un YAML a medio escribir no puede borrar las claves que había; el helper sale con 2 y no toca el fichero. Lo prueba la tarea 1.
- **Valores con caracteres que rompen el formato** (`#`, `:`, comillas, `\n`, espacios de los extremos): deben guardarse literales y proyectarse válidos. Tareas 1 y 2.
- **Proyección con claves ajenas ya puestas** (un `/etc/theHarvester/api-keys.yaml` con claves, el `datasources.yaml` de amass con otras fuentes): no se pierden. Tareas 2 y 4.
- **Herramienta ausente o base sin inicializar**: nunca se inventa estructura ni se saca una traza. Tareas 3, 4 y 5.
- **`pedir` sin terminal** (stdin por tubería, como todas las suites): no se cuelga y no deja el eco como única salida. Tarea 7.

- [ ] **Step 3: Implementar el adaptador**
